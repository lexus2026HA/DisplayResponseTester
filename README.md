# Display Response Tester V1.2

Локальное Windows-приложение для проверки мониторов и телевизоров. Читает параметры видеосигнала и EDID, показывает полноэкранные тестовые паттерны, измеряет интервалы отрисовки Qt и сохраняет отчёты.

## Готовая сборка

Откройте вкладку **Releases** в репозитории и скачайте Windows x64 ZIP. Распакуйте весь архив в доступную для записи папку, затем запустите `DisplayResponseTester-v1.2.exe`. Для слайдшоу добавьте свои JPG/PNG в папку `Images` рядом с EXE.

## Запуск и сборка из исходников

1. Откройте `build/DisplayResponseTester-v1.2.exe`. Сборка для Windows x64 содержит собственный Python.
2. Положите JPG, JPEG и PNG в папку `Images` рядом с EXE. Сборочный скрипт копирует имеющиеся изображения за пределы EXE.
3. Для запуска исходников используйте PowerShell в каталоге проекта.

```powershell
.\setup.ps1
.\run.ps1
.\.venv\Scripts\python.exe -m pytest -q
.\build.ps1
```

Если политика PowerShell запрещает локальные сценарии, используйте `py -3.12 -m venv .venv`, затем `.\.venv\Scripts\python.exe -m pip install -r requirements.txt` и `.\.venv\Scripts\python.exe main.py`. Для запуска из VS Code откройте папку проекта и выберите **Tasks: Run Task → Display Response Tester: Run**. F5 использует Python Debugger, если расширение установлено. Для быстрой проверки и журнала запуска используйте `main.py --smoke`.

Настройки, журнал и отчёты по умолчанию находятся рядом с `main.py` или EXE в папках `config`, `logs` и `results`. Размещайте приложение в доступном для записи каталоге.

## Проверка основных функций

| Вкладка | Порядок работы |
|---|---|
| **Display Info** | Выберите видеовыход вверху. Откройте сведения Windows/EDID, при необходимости уточните панель и подсветку. Нажмите на строку «Модель», «Имя устройства из EDID» или «Спецификация модели», чтобы скопировать значение. Кнопка «Экспорт TXT / HTML» сохраняет параметры выбранного дисплея вместе с источниками данных. |
| **Slideshow** | Выберите Fit или Fill и запустите показ. Стрелки ←/→ переключают кадры, ↑/↓ и +/− меняют интервал в диапазоне 1–5 с, Space ставит на паузу, Esc закрывает. Оверлей выключен по умолчанию. |
| **Motion Test** | Выберите рисунок, скорость, целевой FPS и фон. Pepper, Cart, Airplane и оба варианта Moving Squares используют четыре ряда со скоростями 200%, 150%, 100% и 50%. Для тележки RPM 0 связывает вращение колёс со скоростью. Для Frame Skipping установите целевой FPS около частоты сигнала и сделайте фото с достаточно длинной выдержкой. |
| **Software Latency** | Квадрат отскакивает от границ чёрного поля. ← / → меняют цвет, ↑ / ↓ меняют скорость. В левом верхнем углу видны FPS, средний интервал кадра, P95 и время от запроса перерисовки до начала отрисовки Qt. После Esc итог виден под кнопкой запуска и доступен в отчёте. |
| **Reports** | Добавьте условия и визуальные наблюдения. Экспортируйте HTML, PDF, JSON или CSV. CSV содержит временной ряд аппаратного теста или Simulation. |

В **Moving Squares** положение рассчитывается по прошедшему времени. В **Moving Squares (Frame Stepped)** каждый отрисованный кадр сдвигает квадрат на число пикселей, соответствующее целевому FPS. На экране обоих тестов отображаются FPS, средний интервал отрисовок и P95 за окно около 250 мс. Средний интервал равен времени окна, делённому на число межкадровых интервалов. FPS равен 1000 / средний интервал в миллисекундах. Отдельно выводится среднее время от запроса перерисовки до начала Qt paintEvent по последним запросам. Эти метрики помогают видеть пропуски и нестабильность кадров. Оптический отклик измеряется отдельным аппаратным методом.

В **Local Dimming** Space меняет число и размещение тёмных квадратов. В **Color Transitions** и **Gray-to-Gray Patterns** стрелки переключают экраны, Space включает или останавливает автоматический перебор с интервалом «Длительность уровня». H включает подсказку. Серые экраны содержат ступенчатые и плавные шкалы, кольца, встречные шкалы, шкалы теней и светов, плавную и ступенчатую радиальные шкалы и патч с выбранными уровнями.

Qt Widgets измеряет интервалы между программными отрисовками. Целевой FPS, частота видеосигнала, видимая плавность, GtG и HDMI-to-light описывают разные величины. Показатели Software Latency относятся к генератору кадров Qt. Для измерения отклика панели и задержки HDMI-to-light нужен внешний датчик. Управление VSync из приложения недоступно. В зеркальном режиме Windows полноэкранное окно видимо на всех дисплеях, которые получают один и тот же видеовыход рабочего стола.

База панелей в `config/panels.json` использует ключ `EDID_VENDOR:PRODUCT_HEX`. EDID и драйвер показывают отдельные возможности. Состояние VRR в системе и активность во время теста неизвестны без подтверждения. В частности, рекламу G-SYNC в паспорте модели можно отличить от статуса сертификации.

## Аппаратный тест и Simulation

**Simulation** генерирует детерминированный ряд с явной маркировкой. Предпросмотр показывает синтетический патч для проверки ROI. В Hardware Test выберите два уровня яркости, время удержания и число циклов. Запустите тест, дождитесь таблицы и графика. Esc или «Остановить» завершает запись. Результат автоматически сохраняется в JSON, остальные форматы доступны через «Экспорт».

**Orange Pi по Ethernet** использует независимый клиент [app/hardware_tests/client.py](app/hardware_tests/client.py), OpenCV/V4L2 на агенте и HTTP на порту 8765. Подключите камеру к плате и запустите агент. Укажите IP, подключитесь, выберите устройство, формат, разрешение и FPS. Доступные комбинации и диапазоны V4L2 приведены в «Режимы и управления камеры». Сделайте предпросмотр и выделите ROI внутри центрального патча. Для выбора ROI на той же панели можно вывести тестовый участок на другом экране либо расположить камеру так, чтобы область была в центре кадра. Убедитесь, что экспозиция фиксирована, а картинка сохраняет разницу между уровнями. Настройки, полученные от драйвера, записываются в отчёт. Предпросмотр передаёт уменьшенный JPEG, измерение передаёт только метаданные и ряд ROI.

Кадры отмечаются по времени возврата `VideoCapture.read()` на агенте. Агент отдельно сохраняет длительность чтения, обработки ROI и признаки пропусков. ПК отдельно сохраняет начало и окончание отрисовки патча и RTT запросов. Для оптической оценки 10–90% требуются как минимум четыре последовательных межкадровых интервала на фронте. Оценка и границы дискретизации считаются по соседним отсчётам без интерполяции. Буферизация, выдержка и rolling shutter дополнительно ограничивают точность. 30 FPS даёт около 33 мс между кадрами. Для точного GtG и HDMI-to-light понадобится откалиброванный быстрый датчик и проверенная синхронизация. Экспорт разделяет признак завершения сценария и наличие достоверных переходов.

## Развёртывание Orange Pi One H3

Сначала найдите адрес платы в DHCP-таблице роутера. Подключитесь по SSH и проверьте ОС и камеру.

```sh
cat /etc/os-release
uname -m
ip -brief address
lsusb
ls -l /dev/video*
v4l2-ctl --list-devices
```

На установленном Debian или Armbian с рабочими Ethernet и USB используйте существующую систему. Скопируйте каталог агента и запустите установку после разрешения администратора.

```powershell
scp -r .\orange_pi username@BOARD_IP:~/display-response-agent
```

```sh
cd ~/display-response-agent
sudo sh install.sh
systemctl is-enabled display-response-agent
systemctl is-active display-response-agent
journalctl -u display-response-agent -n 50
curl http://127.0.0.1:8765/health
```

Если нужен новый образ, выберите **Orange Pi One → Debian Minimal (CLI)** на [странице платы Armbian](https://armbian.com/boards/orangepione), проверьте контрольную сумму и выберите нужную MicroSD в Armbian Imager. Перед записью подтвердите устройство и разрешите удаление содержимого. После первого запуска выполните первоначальную настройку Linux по Ethernet и повторите проверки SSH и камеры. После согласованной перезагрузки проверьте `systemctl is-active display-response-agent` и повторите предпросмотр с ПК. Порт предназначен для доверенной локальной сети.

## ESP32-C3 Super Mini по USB

[app/hardware_tests/esp_usb.py](app/hardware_tests/esp_usb.py) реализует отдельный USB CDC-клиент. Hardware Test умеет искать COM-порты и опрашивать совместимую прошивку. Захват с USB-датчика будет проверяться на собранном устройстве. В этой версии GUI проводит сеансы Orange Pi и Simulation. USB-библиотека даёт интерфейс захвата для будущей интеграции.

Протокол v1 использует UTF-8 JSON Lines, COM 115200, 8N1. На запрос каждой строки ожидается строка ответа с тем же числовым `id`.

```json
{"id":1,"operation":"health","data":{}}
{"id":1,"data":{"protocol":"display-response-usb","version":1,"device":"ESP32-C3"}}
```

| Операция | Вход | Ответ в `data` |
|---|---|---|
| `health` | — | `protocol`, `version`, `device`, при наличии возможности датчика |
| `start` | `duration_ms`, `sample_hz` | `session`, `actual_sample_hz` |
| `status` | `session` | `state` (starting, recording, done, error), `sample_count` |
| `stop` | `session` | `state` |
| `samples` | `session`, `offset`, `count` | `samples`, `next_offset`, `done` |

Строка ошибки имеет поля `id` и `error`. Каждый отсчёт содержит `index`, `time_ns` в монотонной шкале прибора, `value` и `gap`. Метаданные прибора должны описывать единицы, источник временных меток, полосу датчика и калибровку. Клиент и тестовый адаптер покрывают обмен сообщениями. Прошивка и проверка точности относятся к следующему аппаратному этапу.

## Проверки V1.2

Автотесты охватывают Windows CCD / EDID, отсутствующий или повреждённый EDID, выбор экрана с одинаковыми моделями и разными координатами, клавиши слайдшоу, режимы движения, программную задержку, FPS, отсутствие камеры, потерю связи, Simulation, USB-обмен через имитацию транспорта и четыре формата экспорта. Реальный ПК используется для проверки активного дисплея и полноэкранного сценария. Многомониторное подключение и физический захват на Orange Pi требуют отдельной проверки на оборудовании.

Функциональные ориентиры для режимов проверки: [TestUFO](https://testufo.com/), [TFT Test](https://tft-test.ru/), [EIZO Monitor Test](https://www.eizo.be/monitor-test/). SVG-объекты в этом проекте созданы для Display Response Tester.
